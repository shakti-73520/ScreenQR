# Verdetto for Android: the threat model

The security pass before launch, item 1 (the work order of 2026-09-06). This
document names the assets, then, for each attacker, every path as a row: the
path, the control as it exists in the code today (the file and the function),
and the test that pins it. It says what is controlled and tested against what.
It claims no state; it names controls and the tests that pin them, and it ends
with the gaps it shows. Private until the repository goes public, then public
as the record. It is a verbiage surface from now on: every product change that
touches a path updates it in the same change.

## 3. A hostile code

A crafted image or payload aimed at the decoder, the parser, the sheet, the
browser or the lookups. The decoder is Rust (`verdetto-core`) with a vendored
C++ engine (zxing-cpp) reached through a handwritten JNI shell
(`verdetto-android`); the parser and everything above it are Kotlin.
